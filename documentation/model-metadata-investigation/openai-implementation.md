# OpenAI implementation progress (2026-09-28)

Commits: `f548a74ca` (native endpoint routing/default), `eef47a3f9` (explicit reasoning overrides). These are incremental, not a complete removal of model-version rules.

- Direct `api.openai.com` connections configured through `goose/src/providers/openai_def.rs` now prefer Responses for model names other than `o1-mini*` when using the default `v1/chat/completions` path; compatible gateways, explicit custom paths, and versionless paths retain old routing. `OpenAiProviderBuilder` defaults to the conservative compatible-provider behavior. Official docs confirm GPT-4o and GPT-6 Astra support Responses, but o1-mini does not. The name-only `o1-mini` exception needs reconsideration for snapshots/aliases, and not every ID available from `/models` can necessarily serve text/tool Responses. Consider catalog tool-call/text metadata or explicit route configuration as the next guard. This preference changes wire behavior for direct OpenAI clients; test against live API before rollout.
- Default model changed from `gpt-4o` to `gpt-5.6-terra` as a balanced cost/quality option listed on OpenAI's model index. This is a product decision with access and price impact; the user may choose another model. No automatic price-based default selection exists.
- Chat and Responses payload formatters now honor explicit `ModelConfig.reasoning` before the legacy family matcher. Canonical reasoning metadata is copied into this field by `ModelConfig::with_canonical_limits`; unknown models still use name fallback. This does **not** replace the model-version effort matrix or remove `o1-mini` guards, because the available live metadata has no endpoint/effort/tool-compatibility guarantees for all aliases.
- Existing `reasoning_mode` version gate and effort translation are retained pending an explicit capability source and real API verification. Blindly deleting these tables could send unsupported `none`, `max`, or `mode` values, and silently clamping Off to Low is not equivalent to disabling reasoning. The native OpenAI routing and payload code remain separately testable.

Validation: `cargo fmt --all`; 53 OpenAI provider unit tests and focused provider-types tests pass; targeted `cargo clippy -p goose-provider-types -p goose-providers --all-targets -- -D warnings` passes. `cargo check -p goose` and workspace clippy could not finish because the local `target/debug/deps/libsqlx_macros-*.dylib` fails to load on macOS with `mis-aligned LINKEDIT string pool` even after deleting the artifact (rebuild yields the same failure). No live API tests performed. Do not interpret this as a validated production migration.

## Follow-up: reasoning_options and legacy model support

Correction: models.dev **does** supply `reasoning_options` with `type: effort` and `values` for many OpenAI models. We had not parsed it. The parser now stores `reasoning_efforts` on `CanonicalModel` (optional for older bundled data); the shared OpenAI effort mapper prefers it over the version table, with the latter retained only for entries without options. The live registry only takes effect after catalog refresh, and the bundled JSON predates this field; a later cleanup can eliminate the version table after bundling/validating current values and defining a policy for unknown/alias models. The user approved dropping o1-mini: removed both shared Chat formatter rejection guards; native OpenAI routes it to Responses if manually configured, which is **not supported** by the OpenAI docs. Do not select it; a future change should reject unsupported non-tool models via authoritative capabilities rather than imply it is usable.

`openai-live-smoke.py` is an opt-in, billed test script (standard library only): run `OPENAI_API_KEY=... python3 documentation/model-metadata-investigation/openai-live-smoke.py` with the key already exported in your shell instead of embedding it in a command or file. It tests a short text response and a tool call, prints usage but not credentials; optionally set `OPENAI_SMOKE_MODEL`. It does not test streaming, replay, or effort. Do not commit any output containing your account metadata.
