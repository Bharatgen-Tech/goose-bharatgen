# Anthropic provider and Anthropic format

`crates/goose-providers/src/anthropic.rs:31,324-326` pins default `claude-sonnet-4-5` but populates known models from the canonical registry. `anthropic.rs:251-405` discovers models through the Anthropic models API, with configured-model fallback on missing endpoint and `dynamic_models: false` for static-only deployments. `fetch_supported_model_info` merges configured values first, then canonical metadata (`goose-provider-types/src/base.rs:373-390`). There is no Anthropic-provider model-name routing table analogous to OpenAI's; the provider always uses the Anthropic Messages wire format. Headers for thinking binding are derived from the outgoing payload (`anthropic.rs:431-460`), not an ID list.

The substantial release-sensitive rule is **outside** this crate: `crates/goose-provider-types/src/canonical/models_dev.rs:24-44` infers `thinking_mode` for an exact list of Claude IDs (Fable 5/5.1, Opus 5/5.5 and 4.6-4.8, Sonnet 4.6/5). An explicit `thinking_mode` field in catalog data wins, otherwise the local table applies. Each new adaptive or always-on variant can need another entry even after models.dev refresh. The same file's `process_model` reads the live reasoning, temperature and thinking fields (`:105-124`). Inspect the actual upstream schema and bundled records before removing the fallback: these inferences may represent missing upstream metadata, not merely stale data.

`formats/anthropic.rs:150-202,828-856` uses the canonical thinking mode to decide adaptive vs enabled vs disabled and whether `thinking: disabled` must be sent explicitly; it consults `reasoning` and `temperature` metadata. Unknown or aliased model names without a matching catalog record may therefore not get the correct thinking mode, even when API discovery returns the ID. Preserve explicit user overrides and safe no-metadata behavior. Shared `ModelConfig::is_reasoning_model` also uses a `claude` substring fallback (`model.rs:292-303`); cache semantics assumes Anthropic-style explicit breakpoints (`cache_semantics.rs:23-36`), including name-based detection for some Anthropic-hosted gateways.

Follow-up verification: test an unseen Claude ID with live reasoning but no thinking mode, an alias with no canonical match, adaptive and always-on Off behavior, temperature disallowed by metadata, and the effect of a catalog update on exact-ID overrides. Do not conflate model API list entries with complete capability metadata.
